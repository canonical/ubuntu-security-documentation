Exim4
=====

Exim4 advertises its service name in response to initial SMTP client connections
(specifically in the 220 greeting banner) and includes its version as part of the
default banner. The version can be removed completely. As covered in the
:ref:`Version banners may not be precise` section, this could lead to false positives
from network vulnerability management scanners.

Disabling the version advertised by Exim4 can be achieved by explicitly defining the
``smtp_banner`` option without the Exim4 ``$version_number`` in the active Exim4 configuration
template, and then regenerating the runtime configuration using ``update-exim4.conf``.

The target/active configuration file to modify depends on whether Exim4 is set up using
split or single (non-split) configuration files (controlled by the ``dc_use_split_config``
option in ``/etc/exim4/update-exim4.conf.conf``):

.. code-block:: text

    Single configuration (dc_use_split_config='false'): File to edit -> /etc/exim4/exim4.conf.template

    Split configuration (dc_use_split_config='true'): File to edit -> /etc/exim4/conf.d/main/02_exim4-config_options

You can verify which scheme your system is using by running ``sudo update-exim4.conf -v`` or
inspecting the header of the generated runtime file (``/var/lib/exim4/config.autogenerated``).

To hide the version, set or uncomment the following line in the appropriate configuration file
and remove/exclude ``$version_number`` from the value:

.. code-block:: text

   smtp_banner = $smtp_active_hostname ESMTP $tod_full

After updating the file, process the template changes with ``update-exim4.conf`` and reload the service:

.. code-block:: console

   sudo update-exim4.conf
   sudo systemctl reload exim4.service
